### Fixed

- **`readsOf` finds a cell spliced as a step of a braid, and a read carries its reference** (#857, #618): a braid's `ref` atom (`&t step=8n &m &m[1:] &m^$7`) has no span of its own (its step has), so the walk that finds every cell a line names passed over it: **803 reads of the 2,990 in the examples** (the commonest read there is) were never seen by `readsOf`, by `reads.test.ts`'s gap list or by a frontend's "every name written is a wire" built on it (Cell studio's, yggi/cell-studio#692, which kept its older regex for the written lines). Each is found now, every one is a wire in the written graph already, and `UNDRAWN` is unchanged. **`Read` gains `ref`** (the reference as the parser read it: its pick, shift, transposition, degree or values' operations, and its slot) **and `span`** (its own, or its step's), so a frontend reads what a name is written with from here and not from the text. New export: `RefAtom`. A frontend that read `readsOf` for the cells a piece names now gets 803 more in the examples: filter by `form` or `path` if it counted on the others only.
