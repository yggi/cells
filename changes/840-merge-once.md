### Changed

- **A learned layer is merged once, not at each query** (#840): `repository.merge(layer)` counts every pair the layer holds (25 ms for a layer of every pair of the library, 35 times a query's own cost), and every query handed a layer merged it again. It is kept by the layer object now, so the same layer merges once and a query with a layer costs what one without costs (0.2 ms where it was 17.6 ms, over the 216-fragment library and 23,220 pairs). Answers are the same. **What a frontend sees:** a layer is read as it was when first merged: filing and use return a new layer (`learned.ts`), which is merged as its own, and a layer grown or shrunk in place is merged again; one changed in place without changing a list's length (a pair's count, say) is read stale, so change a layer by making a new one, as `learned.ts` does.
