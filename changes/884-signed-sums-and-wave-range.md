### Changed

- **A value is what it says: a signed sum, and `sin(n, lo..hi)`** (#884; decision 067 §5 and 096 amended; a hard switch, no migration: the owner, "no migrations anymore before 1.0"): a cell below 0 is no longer read as a bipolar wave, `(1 + x)/2`. As a share, a volume or a parameter's factor it is held at 0; as a term of a sum (079) it is signed, so `&breakdown step=1m -.45` offsets a song downward and a style axis's chain steps downward (`&bite [&funk[bite] + &dsect]` with `&dsect step=1m 0 -.1 -.2`), the sum held to 0…1 where it lands. A wave is written in the range it is read in: a range after the steps, `sin(12, 0..1)` (Strudel's `sine.range(0, 1)`), for `sin`, `saw`, `tri` and `square`; the values are the laid ones, so the braid says what it holds. **What a frontend sees at its next pin:** a piece that patched a wave below 0 into a share (`lpf=200..3000 * &lfo` with `&lfo map=lin loop=.5 sin(12)`) plays its negative half held at 0 (a filter shut half the cycle): write `sin(12, 0..1)`. The seed `lfo` module is written so, and so are the examples. A line below 0 in a sum no longer reads as a share `(1 + x)/2`: `[&song + &breakdown]` with `&breakdown step=1m -.45` reads `.05`, not `.775`. **Events:** `patchbay`'s events and values hashes move (its `lfo` cell holds 0…1 now; its events by at most 0.0022 of a value near 2657, rounding); no note moves; no other example does.
