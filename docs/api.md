# The API

What a frontend imports from `@yggi/cells`, and how that is to be shaped (#724, rung 1 of #713). A decision in the making: the shape below is agreed (the owner, 2026-11-16), and the entry points are added one at a time.

## Today

The root index (`src/index.ts`) is the stated API, but `package.json` also exports `./engine/*`, `./theory/*` and `./repository/*`, so every module is reachable and a frontend can't tell an API from an internal. By the ledger below, Cell studio imports nothing from the root and reaches the package only by module paths; Jambot takes some from the root and the rest by module path.

## The shape: three layers, seven entry points

- **The language:** compile, plan, window, perform, edit, inspect. Entry points `@yggi/cells` (compile and play, and the types they share), `/edit`, `/inspect`, `/midi` and `/time`.
- **The repository:** query, fit, learn, migrate a layer, and a fragment read as cells means it (`reading/*`). Entry point `/repository`.
- **The library:** the seed, styles, the kit, roles, modes and the band, every vocabulary also as a runtime list. Entry point `/library`.

A frontend imports from these and from nothing else. A module path stays reachable (`./engine/*`, `./theory/*` and `./repository/*` stay in `exports`: removing them would break both frontends' pins), but an import from one is **internal**: the ledger names every symbol a known frontend still reaches that way, and a test fails when one of them is renamed or removed, so the move is noticed here and goes in `changes/`. The root index keeps its exports while the entry points are added; a frontend moves its imports when it chooses.

What leaves for Cell studio is the view (decision 086, #731): `routing`, `live`, the show plugins, `graph`'s layout and the hues. The written graph, `values`, `stats` and `time/*` stay: they are facts about a piece.

Each step of the plan moves a count in the ledger: the symbols a frontend reaches by a module path, before and after.

## How the lists are kept

`npm run api` rewrites the part below from `tools/api.ts` (the module-to-entry rules, `ENTRY_POINTS`) and the ledger (`tools/api.ledger.json`); a test fails when this page is stale, when a rule matches no module, when a ledger symbol is no longer exported, and when the page lists a root export that isn't one. `npm run api -- reach <name> <checkout>` measures a frontend again at its pin: its app and its tests and tools apart, by the imports it writes (a dynamic `import()` is not read).
