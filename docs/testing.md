# Testing

What the language's tests promise, a group or a promise to a line; they came from [Cell studio's testing page](https://github.com/yggi/cell-studio/blob/main/docs/testing.md), which keeps the workbench's (layout, audio, the browser checks). Paths are under `src/engine/` unless they say otherwise. `npm run verify` runs the quick ones, `npm run test:all` the slow ones too ([AGENTS.md](../AGENTS.md)).

- Theory: `src/theory/modes.test.ts`.
- Parser: `parser/parser.test.ts`. The syntax reference: `parser/reference.test.ts` parses every example in `[language/reference.md](language/reference.md)` (generated by `tools/reference.ts` from the parser's tables), checks it covers every generator, `map=` kind, unit, modifier, attribute and parameter, and that the committed page is current (record it: `npm run reference`, which also rewrites the README's index of forms). Compile: `compiler/compile.test.ts`, `duration.test.ts`, `physics.test.ts`, `fiveto12.test.ts`.
- Realize (what sounds): `realize.test.ts` (notes, times, levels, per example), `tape.test.ts`, `resonator.test.ts`, `fm.test.ts`, `wave.test.ts`; `edit.test.ts` for line rewrites; `schedule.test.ts` (windows, the engine host).
- Routing (what the graph draws as sounding): `routing.test.ts`: the cases of #11, and for every example that routed and live states agree (live within routed, edges with routed ends, every routed edge drawn), every voice that plays is routed and live while its note sounds, and what moves a voice is routed. The cases that read the graph as drawn are Cell studio's (`src/layout/routing.drawn.test.ts`).
- The tutorial's tiers ([decision 020](decisions/020-tutorial-tiers.md)): `ladder.test.ts` — every form of the reference is on one tier of `ladder.ts` (or in its `STUBS` or `PENDING`), and a tier's pieces (`tags: [tutorial]`, `tier: n` in their frontmatter) use only its forms and earlier tiers' and show all of its own. **New syntax fails here** until it is on a tier with a piece that shows it, or in `PENDING` while it waits for one.
- Examples: `src/engine/examples.test.ts` — every `examples/*.md` file is listed, its text compiles with zero diagnostics, it has a title and tags in its frontmatter and its card's `postgain=` (left out where it is 1) or no card (the built-in card), and it reads the same as written the old way (the card's `title=` `tags=` `tier=`), Shorten's migration writing it byte for byte.
- Snapshot: `src/engine/snapshot.test.ts` — every example's notes over its first 40 s, the values its cells hold at four moments and the live view at three, hashed into one line per piece in `src/engine/snapshot.txt`; a change to what a piece plays fails and names it. Its `notes` column hashes only voice, onset, length and pitch: an `events` hash that changes with `notes` unchanged is a respelling (the tables spell a note differently) or a change in level, pan, bend, parameter or envelope: look. Beside it, for every example: two plans play the same, and 0–30 s plus 30–60 s is 0–60 s. **An intended change** to an example's notes refreshes the file (`npx vitest run src/engine/snapshot.test.ts -u`: about 10 s, measured 2026-10-17 on 4 cores under load; with `-u` before the path, vitest reads the path as `-u`'s value and runs every test, over three minutes), and the PR names the pieces and says why; an unintended one is a bug. Spellings that should play the same (Shorten's check, the equivalence tests) are compared over one length, `SAMENESS_SECONDS` in `src/engine/shorten/harness.ts` (a minute: pieces whose layers turn slower, a day or twenty minutes, are not run to the end). It doesn't see the DSP (renders: `tools/golden.mjs`, #92).
- Equivalences: `src/engine/equivalence.test.ts` — spellings the language promises are equal play the same notes: `map=edo` and `map=ed(2)` (decision 003; at 12, 19, 31, and every example with its default grid written out), `scale(tonic, phase)` and a key and a mode written out (decision 002; six pairs, and every example that uses it), and Shorten run to the end has nothing left to say the second time (every example but BWV 847, for time).
- Fuzz: `src/engine/fuzz.test.ts` — every example with one token or character deleted (a seeded sample of 20 each) compiles, plans and plays its first seconds without throwing. A program with errors plays nothing (`plan` returns no tracks): it may name cells it doesn't have.
- Normalise (`src/engine/normalise/`): `normalise.test.ts` checks each rule (an alias as ours, whatever its length; `clip=` as `legato=`, its warning gone), that the structure is kept and the notes too, idempotence, that every example and seed fragment is normal already (a rhythm read on a 4/4 at a tempo), and that `docs/language/canonical.md` lists every alias; `tools/normalise.test.ts` the command on a `.cells` and a Markdown file, and that every example file is normal.
- Shorten (`src/engine/shorten/`) preserves every note: `shorten/shorten.test.ts` runs `shorten` on every preset; each suggestion is shorter and `sounds()` is identical (events from `plan` + `eventsBetween`). `shortenAll` is tested too.
- BWV 847: `tools/bwv847.reference.json` (written by `tools/bwv847.py`, which downloads the CCARH encoding itself and also writes the text it once wrote as the example, `fixtures/bwv847-generated.cells`) is checked note by note in `realize.test.ts`: onset, length and pitch per voice, as sounded through the tempo map. The example is written by hand (#177), and `sections.test.ts` checks that it plays every note of the generated text over the whole piece, gains too.
- Counterpoint: the Ricercar's passes obey the species rules in `realize.test.ts` (`problems(...)` on what sounds, also per tonos). `tools/counterpoint.py` searched for the lines under the same species rules.
- The folder's ratchet (#307): `src/engine/fold/ratchet.slow.test.ts` takes every example the way a MIDI file comes in (saved as MIDI, opened again), folds it (`engine/fold`) and scores it against the example as written (`fold/score.ts`): its notes kept, its score's size, its phrases back. The totals are compared with `src/engine/fold/ratchet.baseline.json`: no piece that kept its notes may lose them, the phrases back may not fall, the score not grow by more than 1 %. A change worth its trade records the new numbers (`UPDATE_RATCHET=1 npx vitest run src/engine/fold/ratchet.slow.test.ts`), so the PR's diff shows it piece by piece ([notes/ratchet.md](notes/ratchet.md)). Beside it, `src/engine/fold/midiRatchet.ts` folds the MIDI library (`midi/<set>`, every collection, the files as they come; one test file per set, `midi.<set>.slow.test.ts`) against `src/engine/fold/ratchet.midi.<set>.json`: no file whose fold was taken may lose it, a set's score not grow by more than 1 % (recorded the same way: `UPDATE_RATCHET=1 npx vitest run src/engine/fold/midi.`). Both are in the slow project.
- The family's contracts (yggi/music-commons `contracts/`): `src/contracts.test.ts` runs the `euclid` and `notes` vectors, copied into `fixtures/contracts/` (a `lifted` line names the hub's commit; refresh them by copying again), against `bjorklund`, `euclid(k, n, r)`, `x(k,n,r)`, theory's `even`, note names in braids and rates, `noteFrequency`, `noteOf`, `keyOf`, `keyName` and `noteName`. Where cells differs from a vector, a test records what cells does, and the change is the language's to decide.
- The language draws on no chance of its own: `repeatable.test.ts` (Cell studio holds its layout and audio to the same line).
- The repository's own gates: `tools/hooks.test.ts` runs the pre-push hook, the stamp `npm run verify` leaves for it and its pointing git at the hook (`tools/verified.sh`), the session's start and `branch-status.sh` in throwaway repositories, and `tools/test-count.test.ts` the reporter that keeps the count of verify's tests for the stamp (`tools/test-count.ts`); `tools/reading-list.test.ts` holds the boot set (`AGENTS.md` and `docs/MEMORY.md`) under 24 KB. `tools/review.test.ts` runs the review skill's `prepare.sh` against a throwaway origin; `tools/node-ts.test.ts` runs the language under Node. `tools/pianoroll.test.ts` draws the pianoroll skill's pictures (the PNG only where Chromium's headless shell is). `tools/groove.test.ts` runs the Groove MIDI measure ([notes/groove-measure.md](notes/groove-measure.md)) over three of the dataset's files (`fixtures/groove/`) and synthetic performances, and fails when a 2:1 pair's swing share is computed wrongly.

## Gates that show themselves only by failing

What fixes each:

- A generated file gone stale, `src/engine/examples.generated.ts` (`npm run examples`), `src/repository/seed.generated.ts` (`npm run fragments`), `types/` (`npm run types`, after any change to an exported signature) or `dist/` (`npm run dist`, after any change to `src/`), `docs/language/reference.md` (`npm run reference`, which also rewrites the README's index of forms)
- A host global in `src/` beyond the three in `src/host.d.ts` (the purity typecheck, `tsconfig.pure.json`: no command, the code moves out)
- An unguarded index in a folder on the clean list of `tools/strict.mjs` (the strictness ratchet: narrow the value)
- A change in what an example plays (`src/engine/snapshot.txt`: `npx vitest run src/engine/snapshot.test.ts -u` when it is the point, about 10 s, named in the pull request; `-u` before the path takes it as its value and runs every test)
- A new form (an attribute, a generator, a modifier) on no tier of the tutorial (`src/engine/ladder.test.ts`: put it on a tier in `src/engine/ladder.ts` with a tutorial piece that shows it, or in `PENDING` there until it has one)
- A vector of the hub's contracts cells no longer meets (`src/contracts.test.ts` over `fixtures/contracts/`: a decision, no command)
- A MIDI set without its slow test and ratchet file (`src/engine/fold/midi.sets.test.ts`)
- The folder's ratchets, in the slow tests only (`UPDATE_RATCHET=1`, above)
- The boot set, `AGENTS.md` with this page, over 24 KB (`tools/reading-list.ts`: condense it, as a change of its own)
