# Agents

The cells language as a package: a minimal music language where everything is a cell, on top of Strudel's mini-notation; text in, events out, with no host of its own. Its frontends are [Cell studio](https://github.com/yggi/cell-studio) (the workbench) and [Jambot](https://github.com/yggi/jambot) (the interactive, multi-user frontend), each consuming a tag of this repository. **Start with [docs/MEMORY.md](docs/MEMORY.md)**; [docs/INDEX.md](docs/INDEX.md) lists every page. **What to do next:** look first at the central roadmap epic, [#437](https://github.com/yggi/cells/issues/437) (its twin is [yggi/jambot#555](https://github.com/yggi/jambot/issues/555); it follows #81, closed with the summit's musts met). The family of music projects and its rules: [yggi/music-commons](https://github.com/yggi/music-commons).

## Tools

- `npm run verify`: everything a push needs: `check` (the purity gate and the full typecheck), `lint`, `format:check`, `knip`, and the quick tests (a checkout with no `node_modules` gets `npm ci` first, `tools/install-first.mjs`). Its tests wait for the machine's lock, so two verifies from two worktrees never test at once (`tools/heavy.ts`). A pre-push hook runs it and blocks a push that fails; how git is pointed at it, its stamp, its log and its caches: [testing.md](docs/testing.md#run). Never bypass it with `--no-verify`. A branch of prose alone runs `npm run verify:docs` instead (`tools/docs-only.sh` says which).
- `npm run test:all`: the quick and the slow tests (the folder over whole pieces and the MIDI library: 162 s on four cores, 2026-10-17, and 323 s with other agents loading them). Run it when you touch `src/engine/fold/`, `midiimport`, or anything the slow tests read; on a shared machine, run CI on your branch instead (Actions → ci → Run workflow, or `actions_run_trigger` on `ci.yml`) and quote its run.
- `npm run examples`: rewrites `src/engine/examples.generated.ts` from `examples/*.md`; `npm run fragments`, `src/repository/seed.generated.ts` from `fragments/**/*.md`; a test fails when either is stale.
- `npm run reference`: rewrites `docs/language/reference.md` from the parser's tables and the index of forms in `README.md`; a test fails when either is stale. Run it with any change to a parser table, an attribute or a parameter, and commit the result: nothing regenerates on `main`.
- `npm run types`: rewrites `types/` (the declarations a frontend typechecks against, through the `types` condition of `exports`) from `src/`; a test fails when it is stale. Run it with any change to an exported signature.
- `npm run dist`: rewrites `dist/` (`src/` as JavaScript for Node, through the `default` condition of `exports`; bundlers keep the source through `module`); a test fails when it is stale. Run it with any change to `src/`, and commit the result.
- Skills (`.claude/skills/`): `release` (verify `main`, the changelog and version, the owner's tag, the frontends' pins moved), `review` (a pull request in its own worktree, verified, its claims re-run, one review), `pianoroll` (what a text plays as a picture, before and after a change), `land` (a pull request merged by squash on the owner's word, then its issues: closed, its epic ticked, its follow-ups filed; no deploy), `coverage` (a fragment's points placed, or a query's measure changed, with what each style finds before and after). `node --experimental-transform-types --import ./tools/node-ts.mjs` runs the source under Node.
- `npm run structure -- [--cells] <input>...`: a text's structure, decision 049's measure (each leaf a braid writes, one per attribute value, one per cell, over the normal form; names, labels and comments free), for a change that claims a piece more compact; an input is `example:<key>`, a `.md` piece or fragment, or a `.cells` text (`tools/structure.ts`; Shorten ranks by the same measure, `engine/measure.ts`, #157).
- `npm run coverage -- [--facet <f>] [--k <n>] [--between] [--place <json>] [--distance today|window|hinge|whole]`: what each style of `styles` finds, facet by facet: the first fragment's distance (`=` where the second ties it), or with `--facet` the first `k` with their distances; `--place` tries a fragment's points before they are written, `--distance` a change to how a query measures (`tools/coverage.ts`, #540, #644).
- One file while iterating: `npx vitest run src/engine/parser/parser.test.ts`.

## Rules

Enforced (a failing check says so):
- **Pure.** `src/` typechecks with no host types at all (`tsconfig.pure.json`: no DOM, no Node, no bundler); the host globals it may use are the three in `src/host.d.ts`. Nothing here imports a frontend.
- Docs' ```` ```cells ```` blocks compile, `docs/INDEX.md` lists every page, relative links resolve, every decision is in `docs/decisions/README.md`'s list.
- Every example compiles with no diagnostics, a title, tags from the vocabulary, and its card.
- The folder's ratchets: no fold taken is lost, a set's score doesn't grow by more than 1 % (`src/engine/fold/ratchet.*.json`).
- Prettier owns whitespace; ESLint has no errors; knip finds no unused files or dependencies.

Judgment (nothing checks these; you do):
- **The text is the single source of truth.** A change to what the language means changes how the frontends' pieces sound: say so, and keep the examples sounding the same (the event snapshots) unless the change is the point.
- **A release is a tag.** Frontends depend on `github:yggi/cells#vX.Y.Z`, never a branch, and read [CHANGELOG.md](CHANGELOG.md) before they move it: a change a frontend would notice adds a file to `changes/`, and one that breaks a piece names its migration there (Migrate writes migrations). That is a minor version before 1.0, and the frontends' issues say what to migrate.
- A decision with a rationale gets `docs/decisions/NNN-slug.md` (the next number after the highest here or in Cell studio's list, named on its issue before it is written), and its line in `docs/decisions/README.md`'s list (`docs/MEMORY.md` names only the few that shape any change).
- Code lifted from a sibling says where from (`Lifted from yggi/<repo> <path> @ <commit>`).

## Working

- Work on the branch the session gives you; never push to `main`; **agents don't merge**. Open a pull request from the template (`Closes #n`, or `Part of #n` for one rung of an epic; what and why, the commit verified, follow-ups); a **draft** is whatever is not ready to be merged at any time: a proposal, with open work or undecided questions (it doesn't wait on the owner or on a review: those are not what makes a pull request a draft). A pull request out of draft is **ready**: expect it to be reviewed and merged, so open it that way only when nothing is left open. Setting a draft to ready ends the work on it: more work is a different pull request.
- **Just do, no comment:** typos, nits, a local rename, an added test, fixing a check you broke. **Do and say in the pull request:** a fix beside your change that it needs. **File an issue instead of widening it:** anything out of scope you notice. **Stop, push back, recommend:** anything that changes how a piece sounds or what it means (an event snapshot that moves, a form removed or respelled), an invariant of #26 it would break ([laws.md](docs/language/laws.md), decision 083), a vector of the hub's contracts cells would stop meeting, a change to purity or to the source-of-truth rule, anything that could break a frontend at its next pin (its install, its typecheck), a scope far beyond the issue, anything irreversible or outward-facing (a tag). - An issue meant for an agent states each bound as a number (a size, a count, a time), or says "choose it and name it".
- A tool's module and its test live side by side in `tools/` (`tools/<name>.ts`, `tools/<name>.test.ts`); the language's tests sit beside its code in `src/`.
- **CI is a witness, not the gate:** the repository is public, so Actions costs nothing here (#242). The workflow runs `verify` and the slow tests, as two jobs, on every push to a pull request out of draft, nightly on `main`, and by hand (the release's first step). A draft runs nothing. A check runs once per commit: the review skill reuses CI's run on a head it passed. The gate is still `npm run verify` before the push: a red CI on a ready pull request means the gate missed something. Say in the pull request which commit you verified.
